# 국Rule 가상 내비 v2 — 데모 실행 가이드

## 1. 현재 문제점들 (왜 이 도구가 필요한가)

1. **Pleos 에뮬레이터는 위치가 움직이지 않는다.** 국Rule의 판정(스쿨존·버스전용차로·우회전·주정차)은
   전부 좌표 기반인데, 에뮬레이터로는 "차가 경로를 달리는 상황"을 만들 수 없다.
2. **주행 중에는 앱 화면이 막힌다** (Pleos Connect 정책, 풀지 않음). 주행 중 앱이 뭘 판단하는지
   눈으로 보여줄 화면이 앱 안에는 없다.
3. **에뮬레이터 차량 조작판(8088)은 차속·기어·깜빡이만 바꿔준다.** 위치는 여전히 못 바꾼다.
4. 데모가 증거가 되려면 **판정을 데모 코드가 흉내 내면 안 된다.** 웹에 뜨는 경고·과태료가
   앱 바깥에서 만든 연출이면 의미가 없다.

## 2. 그래서 이렇게 구성했다

```
[웹 (브라우저)] ⇄ [중계 서버 · PC :8765] ⇄ (adb reverse) ⇄ [앱 (에뮬레이터)]
   표시만            차량 역할 대행               판단·기록·문장·음성 전부
```

- **앱**: 신호를 받아 실제 엔진(`CoachEngine`)으로 판단하고, 운전자 언어로 문장을 만들어 음성으로 말한다.
  실차 코드와 한 글자도 다르지 않다. 시뮬레이션 기록은 실제 기록과 분리된다(`beginSim`).
- **서버**: 에뮬레이터가 못 주는 것(위치, 또는 시나리오 전체)을 공급하는 "가짜 차량". 판정은 전혀 모른다.
- **웹**: 내비게이션처럼 생긴 표시 화면. 앱이 보낸 문장·기록을 그대로 그린다. 문장을 만들지 않는다.

주행 모드는 두 가지:

|                  | 시나리오 모드                            | SDK 주행 모드                            |
| ---------------- | ---------------------------------------- | ---------------------------------------- |
| 차속·기어·깜빡이 | 시나리오 파일을 서버가 재생              | **8088 조작판 → SDK → 앱** (실신호)      |
| 위치             | 시나리오 파일                            | 서버가 앱이 보고한 차속으로 경로 위 적분 |
| 용도             | 결정적 재현·녹화 (기대값 비교 통과/실패) | 라이브 조작, SDK 연동 증명               |

## 3. 확인 방법 (데모 실행 플로우)

### 3-1. 서버 + 웹 띄우기

```bash
cd tools/cockpit
npm install            # 최초 1회
node server.js         # http://localhost:8765
```

브라우저에서 **http://localhost:8765** 열기. (가짜 앱으로 먼저 보려면 `node test/fake-app.js` —
실앱 테스트 때는 반드시 끌 것, 앱 자리를 뺏는다.)

### 3-2. 앱 설치와 연결

```bash
adb reverse tcp:8765 tcp:8765        # 에뮬레이터 → PC 터널 (adb 재시작마다 다시)
sh gradlew :app:installDebug         # 또는 Android Studio에서 Run
```

앱을 **P 상태에서 한 번 열고 권한을 허용**한다 (위치·CAR_SPEED → 차량 신호 수집 서비스가 시작됨).

확인 포인트: 웹 좌상단 배지가 **"앱 연결됨"**과 **"차량 신호 수신"**(빨간 **"차량 신호 꺼짐"**이면 시작 창에 나오는 권한 명령을 실행), 왼쪽 아래 패널에 **P / 0 km/h**가 떠야 한다.
이 패널은 앱이 SDK로 받은 실차 값이므로, 여기까지 되면 SDK→앱→웹 체인이 산 것이다.

### 3-3. 시나리오 모드 (자동 재생, 녹화용)

1. 웹에서 시나리오 선택 (A: 위반 4종 / D: 전부 준수 / 사례 1: 홍콩 A씨·繁體中文 / 사례 2: 프랑스 B씨·Français) → 모드 "시나리오" → **[주행 시작]**
2. 차가 혼자 달리며 앱이 음성 안내 → 같은 문장이 웹 배너에 뜸 (2초 내)
3. 종료 화면: A는 **3건 · 170,000원**, D는 **0건**, 사례 1은 **2건 · 70,000원**, 사례 2는 **1건 · 60,000원**이고 모두 **통과**가 나와야 정상. 사례 시나리오는 앱이 주행 동안 그 운전자 언어로 바뀌고(사례 1은 화면 繁體中文·음성 영어, 사례 2는 화면·음성 프랑스어), 끝나면 원래 언어로 돌아옵니다.

### 3-4. SDK 주행 모드 (8088 조작판으로 직접 운전)

1. 웹에서 경로(시나리오) 선택 → 모드 **"SDK 주행"** → **[주행 시작]**
2. **8088 조작판**에서 기어 D, 속도 올리기 → 웹의 차가 그 속도로 경로를 달림
3. 스쿨존에서 30km/h 넘기면 → 앱이 실시간으로 음성 경고 + 웹 배너 + 기록 추가
4. 속도 0 → 기어 **P**로 주차 → 10초 뒤 요약 음성과 함께 종료 화면

### 안 될 때 (실측했던 원인 순)

| 증상                               | 조치                                                                                                                                                                                                               |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 앱이 붙었다 끊겼다 반복            | adb 2개(brew/SDK) 충돌. `adb kill-server && adb start-server && adb reverse tcp:8765 tcp:8765`                                                                                                                     |
| 연결됐는데 기어 UNKNOWN·속도 안 뜸 (웹 배지 **차량 신호 꺼짐**) | 서비스 미기동(권한). AAOS는 사용자별 권한: `adb shell pm grant --user 10 com.goodnight.souprules android.permission.ACCESS_FINE_LOCATION` (CAR_SPEED도 동일) 후 앱 재시작                                          |
| 8088 조작이 반영 안 됨             | 앱 체인 검증용 우회: `adb shell am broadcast --user 10 -n com.goodnight.souprules/.debug.DebugSignalReceiver -a com.goodnight.souprules.DEBUG --es gear D --es speed 40` — 이걸로 웹이 바뀌면 조작판→HAL 구간 문제 |
| 웹이 옛 화면                       | 새로고침 (서버가 no-store라 한 번이면 됨)                                                                                                                                                                          |
